## ピクセルソート

**ピクセルソート**は、画像のピクセルを明度などの基準で並び替えることで、独特のグリッチアート表現を生み出す技法です。このスケッチでは `loadPixels()` / `updatePixels()` を使ってピクセルデータを直接操作します。

### 操作方法

| 操作 | 動作 |
|------|------|
| マウス上下 | 明度の閾値を変更（上=低い閾値、下=高い閾値） |
| クリック | 元画像を再生成 |

閾値が低いほど多くのピクセルがソート対象になり、グリッチ感が強くなります。

## アルゴリズムの仕組み

### 1. 閾値ベースの区間検出

全ピクセルをソートするのではなく、**明度が閾値を超える連続区間**だけをソートします。これが自然なグリッチ感を生みます。

```
行のピクセル:  ■■□□□□■■■□□■■
               暗  明るい区間  暗  明  暗
                    ↓ソート↓
```

暗い部分はそのまま残り、明るい連続区間のみ明度順に並び替えられます。

### 2. 明度の計算

人間の目の感度に合わせた加重平均で明度を算出します（ITU-R BT.601）。

```js
function brightness(r, g, b) {
  return 0.299 * r + 0.587 * g + 0.114 * b;
}
```

緑に最も高い係数が割り当てられているのは、人間の目が緑に最も敏感だからです。

### 3. 行単位のソート処理

各行について、閾値を超えるピクセルの連続区間を検出し、その区間内で明度昇順にソートします。

```js
function sortRow(pixels, y, threshold) {
  let x = 0;
  while (x < W) {
    // 閾値を超える区間の開始を探す
    while (x < W && brightness(...) <= threshold) x++;
    const start = x;

    // 区間の終端を探す
    while (x < W && brightness(...) > threshold) x++;
    const end = x;

    // 区間のピクセルを明度でソート
    segment.sort((a, b) => a.bright - b.bright);
  }
}
```

## loadPixels() と updatePixels()

p5.js でピクセルを直接操作するための API です。

```js
p.loadPixels();          // pixels[] 配列にピクセルデータを読み込む
// pixels[i]   = R (赤)
// pixels[i+1] = G (緑)
// pixels[i+2] = B (青)
// pixels[i+3] = A (透明度)
p.updatePixels();        // 変更した pixels[] をキャンバスに反映
```

1 ピクセルあたり 4 要素（RGBA）なので、座標 `(x, y)` のインデックスは `(y * width + x) * 4` になります。

### pixelDensity(1) の重要性

Retina ディスプレイなどでは `pixelDensity()` がデフォルトで 2 になり、`pixels[]` の実サイズがキャンバスの 4 倍になります。ピクセル操作を行う場合は `pixelDensity(1)` を設定して 1:1 対応にするのが安全です。

## プロシージャル画像の生成

外部画像を使わず、コードで元画像を生成しています。

- **背景グラデーション**: `lerpColor()` で上下に色が変化
- **ノイズテクスチャ**: `noise()` でピクセルごとに明度を揺らす
- **カラフルな円**: 半径を変えながら半透明の円を重ねてグラデーション状に
- **斜めストライプ**: 薄い白線でテクスチャを追加

これにより、ソートしたときに色の帯が美しく流れるような素材になります。

## 試してみよう

- マウスをゆっくり上下して、閾値の変化でソートされる範囲がどう変わるか観察してみましょう
- `brightness` の代わりに色相（Hue）や彩度（Saturation）でソートするとどうなるか試してみましょう
- ソート方向を縦（列単位）に変えるとまた違ったグリッチ感が得られます
- `segment.sort` を降順にすると明暗が反転したグリッチになります
